## 2026-09-02 한계를 캐릭터로 — 기대치 관리 (같은 브랜치)

오너의 걱정: 「100번 잘해도 한 번 못 알아들으면 유저는 실망한다.」 맞는 말이고,
규칙 기반인 이상 못 알아듣는 날은 **반드시 온다.** 그래서 정확도를 더 올리는 대신
**언제 말하느냐**를 바꿨다.

- **실패한 뒤에 말하면 변명이고, 첫날 미리 말하면 신입의 성실함이다.**
  첫 만남 인사 풀(기록 0건일 때만 나가는 자리)에 두 줄 추가:
  「집사는 아직 신입이라 주인님 말을 다 알아듣지는 못한다냥.
  **그래도 받아 적는 건 틀리지 않는다냥.**」
  방점은 「못 알아들을 수 있다」가 아니라 **「그래도 기록은 정확하다」**에 둔다.
- 인용 반사 4줄 → 7줄. 새 줄은 전부 「해석은 안 붙이고 원문 그대로 둔다」 쪽이다.
  사과하면 못 알아들은 게 사건이 되고, 정확히 받아 적으면 그건 그냥 이 집사의 일이다.
- 범용 폴백 3줄 → 8줄. 제일 자주 열리는 그물인데 제일 얇았다.
  **여기서 되묻지 않는다** — 접수원은 모든 말에 논평할 의무가 없다.

전부 확인(조사 교정 포함).

포지셔닝 메모: 이 앱은 **대화 앱이 아니라 기록 앱**이다. 「무엇이든 이해하는 AI 친구」로
소개하면 채팅 지능으로 심판받고, 「하루를 접수해주는 집사」로 소개하면 다마고치의

### 새로 생긴 개념 두 개

- **활동 가드와 감정 가드는 따로 논다.** 제3자 가드가 활동에만 있어서 같은 오해가
  감정 쪽으로 돌아 들어왔다. 한쪽에 가드를 넣으면 다른 쪽도 본다.
- **규칙에 어미를 통째로 묶으면 활용형이 통째로 빠진다.** 위생 규칙이
  `씻었|씻음|씻을`이라 「씻고」를 못 잡는다. 다만 이건 **고치지 않는다** —
  「씻고」를 넣으면 「씻고 싶어」까지 활동이 된다.

## 2026-08-31 냥이가 더 알아듣게 — 이해·대사 라운드

오너 요청: 「대사가 더 풍부해지고, 유저 말을 더 잘 이해했으면」.
실제 입력 40여 개를 넣어보니 **대부분이 `fallback`으로 떨어진 뒤 인용 되묻기로
흘러가고 있었다.** 그 되묻기가 깨져 있었던 게 진짜 문제였다.

```
· 고양이가 아파서 병원 데려갔어 → ‘고양이가 아파서 병원’라고 했구냥. 제대로 이해한 게 맞냥?
· 너랑 얘기하니까 좀 낫다      → ‘너랑 얘기하니까 좀’라고 했구냥. 제대로 이해한 게 맞냥?
```

### 층 1 — 어휘 (`message-interpreter.js`)

| 추가 | 잡히는 말 |
|---|---|
| `conflict` | 싸웠·다퉜·틀어졌·혼났·헤어졌·손절 |
| `swamped` | 정신없·눈코 뜰 새·치였·바빴·쉴 틈 없 |
| `goodnews` | 붙었·합격·뽑혔·당첨·승진·취직·계약·화해했·잘 풀렸 |
| `sad` 확장 | 울었·펑펑 — **tired보다 먼저 받아야** 「쉬어라냥」으로 안 흘러간다 |

고친 오분류 2건:
- **「머리 자르고 왔어」가 인사였다.** `왔어`를 아무 데서나 잡고 있었다 →
  문장 맨 앞에 홀로 설 때만 인사(`^\s*(?:나\s*|이제\s*)?왔(?:어요?|다)`).
- **「약 먹는 거 까먹었어」가 「식사 챙김」 대업이었다.** `까먹`·`빼먹` 안의
  「먹」을 세고 있었다 → 앞 글자 한 칸을 본다(`(?:^|[^까빼])(?:먹었|먹고)`).
  lookbehind는 쓰지 않는다 — 구형 iOS Safari에서 파일이 통째로 죽는다.

### 층 2 — 되읽기 (`chat-engine.js`)

| 규칙 | 왜 |
|---|---|
| **잘린 인용 금지** | 12자에서 자르면 서술어가 날아간다(「고양이가 아파서 병원」). 통째로 읽을 수 있는 절만 인용하고, 길면 다음 절을 본다. 없으면 인용을 포기한다. 한도는 17자 |
| **완결 어미 검사**(`QUOTE_TERMINAL`) | 「-고 / -다가 / -는데」에서 잘린 절은 어간만 남는다(「머리 자르」). 받침 ㅆ 검사만으로는 안 걸려서 끝 글자를 직접 본다 |
| **확인 구하지 않는다** | 「제대로 이해한 게 맞냥?」은 못 알아들었다는 광고다. 되읽기는 **받았다는 표시**여야 한다 |
| **애씀·바람이 인용보다 먼저** | 그건 뜻을 읽은 답이고, 인용은 그 밑에 깔린 그물이다 |

새로 받는 자리 4개: 남을 돌본 하루(반려동물·가족 포함, 성과로 안 센다) ·
아직 안 한 일(재촉 없음) · 아찔했던 순간 · **고맙다는 말이 안 나온 감사**
(「너랑 얘기하니까 좀 낫다」 — 집사는 공을 자기 쪽으로 당기지 않는다).

### 층 3 — 풀 두께

고양이 인텐트 대사 **3줄 → 6~7줄**(26개 전부). 3줄이면 같은 말을 사흘 만에
다시 듣고, 그 순간 집사는 사람이 아니라 자판기가 된다.

### 여기서 배운 것

- **폴백이 좋아지면 분류를 안 고치게 된다.** 반대다 — 폴백이 자주 나가면 그건
  분류가 못 따라온다는 신호지, 폴백을 예쁘게 다듬을 이유가 아니다.
  이번 라운드도 되읽기부터 손댔지만, 실제 개선은 층 1에서 나왔다.
- **규칙 기반의 한계는 여기까지다.** 어휘를 넣은 만큼만 알아듣는다. 진짜
  「이해」로 가려면 LLM 호출이 필요하고, 그건 비용·프라이버시(주인님 하루가
  외부로 나간다)·오프라인 동작을 오너가 먼저 정해야 하는 문제다.
  에이전트가 임의로 붙이지 않는다.

검증: 회귀 **9/9 fixtures · 158 checks**, node 스위트 2종(이해 계약 assertion 추가).

### 여기서 배운 것 (같은 함정 두 번 밟지 말 것)

- **완료 판정을 넓힐 때는 반드시 「하려고 했는데」·「하고 싶었어」·「하려다 말았어」를
  같이 돌려본다.** 한국어 과거형 어미(ㅆ)는 의도·미완·포기에도 그대로 붙는다.
  넓히는 규칙은 허용 목록으로 짠다 — 막는 목록으로 짜면 반드시 샌다.
- **어제를 언급하는 기능은 「어제 기록이 있을 때만」이 조건이다.** 공백을 건너뛰어
  이으면 그 순간 감시가 된다.

## 완료 기록 1 — A-1 홈 CTA가 첫 화면 밖이다

감사에서는 `아쉬움`·360px 문제로 분류됐지만, 재측정 결과 **세 폭 전부**였다.

기록 없는 고양이 계정을 최상단으로 열었을 때 (viewport 높이 800):

접수 버튼은 세 폭 모두 화면 밖이고, **입력창도 아래 절반이 고정 nav에 가려진다.**

### 제약

HOME 구조·집사방·어제 일기 통지는 **LOCKED**다. 없애거나 순서를 바꾸는 방향은 안 된다.

### 절차

- 무엇을 얼마나 바꾸는지 (구체적 수치)
- 세 폭에서의 예상 좌표 (입력창 / 접수버튼 / nav)
- 잃는 것 — 특히 집사방이 작아지면 방에 놓인 물건이 얼마나 작아지는지
- LOCKED 표의 어떤 행과 닿는지

## 완료 기록 2 — B-2 legacy 인증서 모순

legacy `achievements`의 `isCertificate !== false` 항목이 전부 `state.certificates`로
이관되는데, 진행도는 `officialRecords().length`로 따로 계산한다. 그래서 파일 화면에
**「공식 인정 4건」과 「5건이 모이면 발급합니다 (1건 남음)」이 동시에** 뜬다.

### 먼저 오너가 답해야 하는 것

> 예전 버전에서 받은 기념 증서를, 지금의 "공식 인정"으로 쳐줄 것인가?
>
> - **(가) 쳐준다** — 옛 4장이 공식 인정으로 남고 진행도 계산도 그것을 반영한다. 옛 사용자를 존중하는 쪽.
> - **(나) 별개로 둔다** — 옛 증서는 보관하되 공식 인정 계보에는 넣지 않는다. 계산이 깨끗한 쪽.
>
> 실제 legacy 사용자가 거의 없다면 (나)를 권한다.

**오너 결정: (나) — 옛 기념 증서는 공식 인정 계보에서 분리한다 (2026-08-22 확정).**

즉 공식 인정은 새 규칙(첫 5건, 이후 7건 주기)으로만 센다. 옛 기념 증서는
삭제하지 않고 보관하되, 진행도 계산과 발급 회차에는 넣지 않는다.
「공식 인정 4건」과 「1건 남음」이 동시에 뜨던 모순은 이 기준으로 없앤다.

### 수리 조건

- **기존 저장 데이터를 절대 삭제하지 않는다.** 어떤 결정이든 옛 증서는 보관된다.
- `butlermaker_v1` 저장 계약에 새 키를 늘리지 않는다. 파생으로 되면 파생으로 한다.
- 인증서 회차 숫자(`certificateTargetFor`)는 과거 증서를 다시 열었을 때도 그때의
  목표를 말해야 한다 — LOCKED 「인증서 숫자」 행.
- `tests/personnel-migration.html` fixture로 실제 재현하고, 수리 후 같은 fixture에서
  두 표시가 일치하는지 확인해 보고한다.

## 완료 기록 3 — A-2 마이그레이션 테스트가 검증을 하지 않는다

`tests/legacy-migration.html`, `tests/diary-reveal.html`, `tests/personnel-migration.html`
셋 다 localStorage만 심고 앱으로 이동한다. **B-2 모순이 화면에 그대로 나타났는데도
테스트 실패가 되지 않았다.**

fixture 역할은 유지하되 핵심 계약에 assertion을 붙인다:

- 이관된 인증서 수와 진행도 안내가 서로 모순되지 않는가
- legacy source fallback (`records`가 없으면 `achievements` 사용)이 동작하는가
- 같은 날짜에 legacy 공개 일기와 신규 봉인 일기가 섞였을 때 공개가 우선인가

기존 두 스위트(`node tests/*.test.js`)처럼 CLI에서 돌릴 수 있으면 그게 낫다.
브라우저가 꼭 필요하면 그 이유를 적는다.
