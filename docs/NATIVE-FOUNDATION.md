## A. 확정된 결정 (오너 승인, 다시 논의하지 않는다)

### A-1. 배포: 앱 100%, 웹은 간판만

- 제품은 iOS/Android 앱으로만 낸다. **Capacitor 래핑** — 바닐라 JS 코드를 그대로 쓴다.
  네이티브 재작성 금지.
- 웹은 소개·스토어 링크·개인정보처리방침·고객지원만 남긴다
  (방침 URL과 지원 연락처는 스토어 심사 제출 요건이다).
- 결제는 웹 PG가 아니라 **스토어 IAP** 기준으로 설계한다.
  entitlement 관리는 RevenueCat(공식 Capacitor SDK 있음).

### A-4. 왜 결제보다 저장소가 먼저인가

모바일 웹뷰의 `localStorage`는 OS가 용량 정리 중 **지울 수 있다.**
파일이 재산인 앱에서 이건 "치즈냥이 주인님을 잊는" 사고다. 예쁜 발령장보다
치즈냥이 어제를 기억하는 것이 먼저다. 그래서 순서가 이렇다:

1. ~~P0 브랜치 main 머지~~ — 완료 (`0f23fb5`)
2. **Native Foundation 1차** ← 이 문서 B (Capacitor + 저장소)
3. 네이티브 최소 세트 (햅틱·로컬 알림·공유·수명주기)
4. RevenueCat + 수익화 상태 (무료/발령 플래그, 후원, 복원)
5. 정식 발령 UX (신청서 → IAP → 발령장) — 마지막에 실결제 연결

## B. Native Foundation 1차 — 작업 지시서

**범위: Capacitor 셋업 + StorageAdapter + 1회 마이그레이션. 그게 전부다.**
UI·기획·대사·수익화 코드는 이 단계에서 건드리지 않는다.

### B-1. 저장소 현황 (2026-09-01 전수 조사)

localStorage 접점은 좁다. 이것만 관문 뒤로 보내면 된다:

| 파일 | 접점 | 키 |
|---|---|---|
| `app.js` 1464–1465 | 읽기 | `butlermaker_v1`, `overbutler-v2-state`(레거시, 읽기 전용) |
| `app.js` 1487, 7920 | 쓰기 | `butlermaker_v1` |
| `cat-conversation-memory.js` 11, 86 | 읽기+쓰기 | `butlermaker_v1` |

### B-2. StorageAdapter 계약

- 단일 관문: 앞으로 어떤 코드도 `localStorage`를 직접 만지지 않는다.
  `Storage.loadState()` / `Storage.saveState(serialized)` 류의 한 모듈만 통한다.
- 어댑터 2종: **web**(= 기존 localStorage, 키 이름 그대로) / **native**(Capacitor
  Preferences, 나중에 SQLite로 교체 가능한 구조).
- **동기/비동기 함정**: 지금 앱은 부팅 시 동기로 상태를 읽는다. Preferences는
  비동기다. 패턴: `await Storage.init()`을 `init()` 앞에 한 번 — 이때 네이티브
  값을 메모리로 올리고, 이후 읽기는 메모리에서 동기로, 쓰기는 메모리 갱신 후
  비동기 플러시. 앱 로직의 동기 가정을 바꾸지 않는 것이 목표다.
- **웹에서는 바이트 단위로 기존과 동일하게** 동작해야 한다. 회귀 하네스
  (`tests/`)가 localStorage에 직접 seed를 심는 구조라, 웹 어댑터가 같은 키를
  쓰는 한 기존 fixture 9종이 그대로 돌아야 한다. fixture 수정 금지.

### B-3. 마이그레이션 (첫 네이티브 실행 1회)

```
native 저장소에 butlermaker_v1 있음? → 그것이 source of truth. 끝.
없음 → localStorage에 butlermaker_v1 있음?
  → 있으면: native로 복사 → 다시 읽어 파싱·핵심 키 검증(roundtrip)
     → 성공 시에만 native를 source of truth로 전환
  → 없으면: 신규 사용자. native에서 시작.
```

- **어떤 실패 경로에서도 기존 데이터 삭제 금지.** localStorage 원본은
  마이그레이션 성공 후에도 지우지 않는다(비상 사본).
- 검증 실패 시 localStorage로 계속 동작하고, 다음 실행에 재시도.

### B-4. Capacitor 셋업 원칙

- 프로젝트 루트가 곧 웹 자산이다(빌드 없음) — `webDir` 설정으로 그대로 포장.
- 이 단계에서 붙이는 플러그인은 Preferences뿐. 햅틱·알림·공유는 3단계.
- 웹 배포(Vercel)가 깨지면 안 된다. Capacitor 설정 파일이 추가될 뿐,
  index.html을 브라우저로 열었을 때의 동작은 지금과 동일해야 한다.
