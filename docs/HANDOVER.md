## 2. 아키텍처에서 반드시 알아야 할 것 넷

### ① CSS는 13장이고 마지막이 이긴다

`index.html`의 로드 순서가 곧 우선순위다.

```
app.css → home-final → records-final → manager-final → certificate-final
→ report-final → flow-final → reaction-final → relationship-final
→ ux-polish → contextual-response → home-office → retro-office.css
```

- **`app.css`가 첫 번째라 가장 약하다.** 여기 고쳐놓고 "왜 안 먹지" 하기 쉽다.
- 실제 시각 작업은 대부분 **`retro-office.css`(4,470줄, 맨 마지막)**에서 한다.
- 같은 특정도면 뒤가 이긴다 — 새 규칙은 파일 끝에 붙이는 게 가장 확실하다.

### ② 집사 탭 화면 순서는 DOM이 아니라 flex `order`가 정한다

`#view-manager .manager-details { display: flex }` (`manager-final.css:221~`).
DOM만 옮기면 **아무것도 안 바뀐다.** 그리고 **order를 빠뜨린 카드는 기본값 0으로
잡혀 헤더보다 위로 튄다** — 설정 카드가 실제로 그랬다. 카드를 추가하면 order를 반드시 준다.

### ③ 접수대 방(고양이 홈)의 좌표계

방은 세 겹으로 겹쳐 있고, 각 층이 서로를 가린다.

```
z 0  .cat-home-background   방 배경 (월드 = 방 폭의 155%)
z ?  .cat-home-character    고양이
z 4  .cat-home-foreground   책상 앞판 — bottom 28%부터 아래를 덮는다
z 5  .cat-room-gifts        선물·흔적 레이어 (전경보다 위에 있어야 책상 앞쪽에 놓인다)
```

- 좌표는 전부 **월드(155% 폭) 기준**. 기본 화면에 보이는 구간은 **18~82%**뿐이라, 상시 노출 아이템은 이 안에 넣어야 한다.
- 고양이는 가로 **41~59%**, 세로로 위에서 **75%**까지 차지한다.
- 접수 슬립이 방 아래 **11%**를 덮는다.
- 배치는 두 벌이다 — `CAT_ROOM_LAYOUTS.desk` / `.tower`(세로 가구가 설 때). 자세한 건 LOCKED 표 「집사방 물건」 행.

### ④ 월드가 포인터를 캡처해서 자식 버튼에 `click`이 오지 않는다

방을 잡아 끌 수 있게 하려고 pointer capture를 쓰는 탓이다.
**방 안에 버튼을 새로 넣으면 click 리스너는 절대 안 불린다.**

- 실제 처리는 `endCatHomeDrag()`에서 한다 — 누르고 안 민 채로 뗐을 때 직접 호출.
- `click` 경로는 키보드 Enter 전용으로 남겨두고 `event.detail > 0`으로 구분한다.
- 이걸 모르면 "코드는 맞는데 아무 반응이 없는" 상태로 한참 헤맨다. R3에서 실제로 그랬다.

## 3. 저장 계약 — 여기서 사고가 난다

키는 `butlermaker_v1` 하나. `normalizeState()`가 로드할 때 누락 필드를 채운다.

### 규칙 셋

1. **새 키를 함부로 늘리지 않는다.** 파생 계산으로 되면 파생으로 한다(파일 표지 수치가 전부 그렇다).
2. **키를 추가하면 `normalizeState()`에 기본값을 반드시 넣는다.** 안 넣으면 기존 사용자에서 `undefined`가 굴러다닌다.
3. **상수 선언 위치를 조심한다.** `normalizeState()`가 참조하는 상수를 그 함수보다 **아래**에 선언하면 TDZ로 `ReferenceError`가 나고 **앱 전체가 부팅 실패**한다. R2에서 `DESK_PLATES`가 그랬다. 새 상수는 파일 상단 상수 정의부(`APPLICANT_ORDER` 근처)에 둔다.

### 선물 이름은 특히 위험하다

`giftHistory`는 선물을 **이름 문자열**로 저장한다. 카탈로그에서 이름이 사라지면
그 선물은 방에서도 보관함에서도 **조용히 없어진다** — 집사가 "하나도 안 버렸다냥"이라고
말하는데 실제로는 버려진 셈이 된다.

→ 읽는 쪽은 전부 **`giftHistoryFor()`**를 거친다. 옛 이름을 새 이름으로 바꿔 보여주되
**저장 배열 자체는 손대지 않는다**(롤백 가능). 품목 이름을 또 바꿀 일이 있으면
`CAT_GIFT_RENAMES`에 줄을 추가하면 된다.

예외 하나: **감사 편지**는 그때의 이름을 그대로 둔다. 편지는 그날 쓴 문서라,
머리말만 새 이름으로 갈면 본문과 어긋난다.

## 4. 절대 넘지 않는 선

이건 취향이 아니라 제품 정체성이다. 어기면 앱이 다른 물건이 된다.

### 감시 / 기억 경계
- **기억(써도 됨)** — 유저가 제출한 내용에 대한 통계. 최다 대업, 총 기록 수, 기록된 날.
- **감시(쓰면 안 됨)** — 행동 패턴에 대한 통계. **접속 시간대 · 공백일 · 부재 언급 · 스트릭.**
- 미접속 표현은 "오늘 접수 0건" 단일 판정의 자리 흐트러짐뿐이다. 며칠인지 세지 않는다.

### 죄책감 금지
해고·퇴사·소멸·관계 하락·스트릭 패널티 — 전부 없다. 안 와도 벌이 없어야 한다.

### 시각 위계
- **금박은 인증서·축하에만.** 평상 화면에 금색이 돌면 인증서가 특별해지지 않는다.
- **`--hand`(Gaegu)는 집사가 손으로 쓴 것에만** — 소견·일기·서명·심사 혼잣말. 시스템 문구에 쓰면 "누가 썼는가"의 위계가 무너진다.
- 공문은 `--serif`(Song Myung, **400 단일 웨이트** — 굵기를 요청하면 안 뜬다).

### 모션
- **컨페티·파티클·화려한 트랜지션 금지.** transform/opacity만 쓴다.
- 한 순간에 움직이는 것은 하나뿐.
- 기울기는 `transform`이 아니라 **`rotate` 속성**에 넣는다 — 같은 속성에 두면 착지 애니가 기울기를 덮어쓴다.
- `prefers-reduced-motion`에서는 클래스를 아예 안 붙여 즉시 최종 상태로 가고 진동도 끈다.

### 어휘
- **청구서·대장·단가처럼 계산적인 말 금지.** 선물은 거래가 아니다.
- 호칭은 "네/너"가 아니라 **"OO 주인님"**.
- 고양이 대사는 **1문장 + 꼬리**. 길면 화면에서 잘린다(아래 참고).

## 5. 대사를 건드릴 때

### FORM05는 소견의 첫 문장만 싣는다

`firstSentenceOf()`가 첫 문장만 남긴다(12자 미만이면 두 문장).
그래서 **태도는 반드시 첫 종결부호(`.` `!` `?`) 앞에 들어가야 한다.** 뒤에 두면 화면에서 잘린다.
사무 정보와 태도를 한 문장에 묶을 때는 마침표 대신 `…`를 쓴다.

> R1에서 1단계 데레 4줄이 이것 때문에 통째로 잘렸다.

### 조사는 하드코딩하지 않는다

`fillContentTemplate(message, { gift: name })` 형태로 **값을 넘겨야** 조사가 맞춰진다.
`{gift}`를 `replaceAll`로 먼저 갈아끼우면 교정기가 볼 게 없어져서 **"츄르은"**이 나간다.
(`agreeParticle()`이 한글 종성으로 판별한다.)

### 다른 캐릭터 대사는 손대지 않는다

고양이 하나를 완성도 기준으로 삼는 게 잠긴 방향이다(CAT-FIRST).
AI·외계인 등은 **기존 기능이 깨지지 않게만** 유지한다.

## 6. 에셋 규칙

### 이미지
- 런타임은 **webp**만 읽는다. **원본 PNG는 저장소에 남기고 배포에서만 뺀다**(`.vercelignore`).
- 변환: `quality=90, alpha_quality=100`.
- **알파 여백을 잘라내고 만든다.** 여백이 남으면 화면에서 상자만 커지고 물건은 그대로다 — 눈에는 아무것도 안 겹치는데 판정만 겹친다. R5에서 창가 방석이 그랬다.
- **원본 PNG를 삭제하지 않는다. 이미지 경로 구조를 바꾸지 않는다.**

### 방에 놓는 아이템
- 크기는 **폭이 아니라 높이**로 잡는다. 가로세로 비가 0.46(캣타워)~1.62(쥐 인형)까지 벌어져서, 폭을 맞추면 세로로 긴 게 화면을 뚫는다.
- 그림에는 외곽선과 접지 그림자가 **이미 그려져 있다.** 런타임에서 `drop-shadow`를 또 얹으면 그림자가 두 겹이 된다.
- 새 선물 그림을 만들 때는 `design/gift-assets/GIFT-PROMPTS.md`의 공통 프롬프트를 그대로 쓴다. **한색(파랑·보라) 금지**가 거기 들어 있다 — 방 배경의 한색 비율이 0.3%라, 파란 물건 하나가 "다른 게임에서 가져온 아이콘"으로 읽힌다.

### 날짜 형식 함정

앱의 `today()`는 **`"2026.08.20"`** 형식이다. 테스트에서 `toISOString().slice(0,10)`
(`"2026-08-20"`)로 시드하면 "오늘" 필터가 0건이 되어 엉뚱한 결과가 나온다.
`Intl.DateTimeFormat('ko-KR', ...)`로 만든다.

### Native Foundation 부팅은 웹과 네이티브가 다르다

- 웹 `index.html`은 `storage-adapter.js`를 먼저 읽고 기존 classic script 순서로
  동기 부팅한다. 회귀 fixture가 `load` 직후 `window.OVERBUTLER_TESTS`를 읽기 때문에
  웹까지 module bootstrap으로 합치면 하네스가 앱 준비보다 먼저 달린다.
- 네이티브 패키지만 `scripts/prepare-native-web.mjs`가 `www/index.html`을
  `storage-bootstrap.js` module 부팅으로 치환한다. 여기서 `await Storage.init()` 후
  앱 스크립트를 순서대로 읽는다.
- 따라서 웹 9/9 회귀는 저장 계약을 지키지만 **네이티브 부팅 경로 자체를 실행하지는
  않는다.** 실기기 QA에서는 첫 설치와 완전 종료 뒤 cold boot 때 빈 화면 없이 홈이
  뜨는지까지 데이터 보존 확인의 선행 조건으로 본다.
- `design/` 전체를 복사하지 않는다. staging 스크립트의 화이트리스트만 복사하며
  2026-09-02 기준 `www/`는 9.0MB다. `dist/`·`output/`·`prototype/`·원본 PNG는 없다.
- 폰트는 아직 외부 CDN이다. 로컬 폰트 번들은 B파트(StorageAdapter) 범위 밖이며,
  다음 네이티브 최소 세트에서 오프라인 첫 실행과 함께 처리한다.

- `git push --delete`가 403이라 원격 브랜치 삭제가 안 된다. 로컬에서 해야 한다.
- 원격 브랜치가 29개 쌓여 있다. 정리는 승인됐으나 위 제약으로 미완.

## 9. 마지막 한 가지

이 앱에서 가장 쉽게 망가지는 건 코드가 아니라 **톤**이다.

근본은 `docs/WORLD.md`에 있다 — 집사는 직업이라서 챙기는 게 아니라
주인님을 필요로 하는 존재이고, 주인님의 기록이 그 삶의 동력이다.

집사는 물건을 "좋아서" 뒀다고 절대 말하지 않는다. 담당이 주인님 하나뿐이라
주인님에게 받은 건 전부 **업무 관련 물품**이라는 게 집사의 공식 입장이다.
비품팀 반납 요청은 기각이고, 인수인계 목록에서 그것만 빼놨고, 이유는 말하지 않는다.

새 대사를 쓸 때 이 온도를 넘으면 — 대놓고 다정해지면 — 캐릭터가 무너진다.
**자라는 것은 볼륨이 아니라 새어나오는 마음이다.**
