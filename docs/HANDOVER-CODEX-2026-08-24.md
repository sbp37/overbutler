# CODEX HANDOVER — CAT-FIRST 작업선 (2026-08-24)

이 문서는 `docs/HANDOVER.md`를 대체하지 않는다. 공통 구현 함정은 기존 문서를 따르고,
여기서는 Codex가 작업을 이어받은 뒤 확정된 제품 방향과 현재 CAT-FIRST 상태를 전달한다.

## 2. 지금 제품이 풀고 있는 관계

- 치즈냥에게 주인님은 첫 담당이자 유일한 담당이다. 직업이라 기계적으로 챙기는 것이
  아니라, 주인님이 들려준 기록이 신입 집사의 일과 삶을 만들어준다.
- 초반에는 까칠한 츤데레보다 신입의 설렘, 책임감, 서툰 열정이 먼저 보여야 한다.
  츤은 문장 끝에 아주 조금만 남긴다.
- 관계가 자라면 치즈냥도 함께 성장한다. 사무국에서 인정과 칭찬을 받고
  `들뜬 건 아니다냥`, `주인님 덕이다냥`처럼 기쁨이 새어나오는 흐름이다.
- `감사실 적발`, 문책, 감시, 부재시간 계산, 평소 접속시간 추론, 스트릭, 미완료 압박은
  세계관과 충돌한다. 집사는 사용자가 직접 적어준 내용만 안다.
- 다른 캐릭터는 삭제하거나 포기한 것이 아니라 차례를 기다리는 중이다. 현재 수정은
  고양이에만 한다.

## 3. Codex 작업선에서 확정된 큰 변화

### 기록과 집사 일기

- 새 기록은 가능한 범위에서 `sourceText`, `discoveredAchievement`, `reactionLines`를
  함께 보존한다. 상세에는 내가 들려준 이야기, 집사가 발견한 대업, 당시 반응이 분리돼
  보인다.
- legacy 기록은 `sourceText`가 없으면 기존 `deed`/`report`를 사용한다. 기존
  `butlermaker_v1` 데이터를 깨지 않는다.
- 당일 집사 일기는 기록 수와 짧은 티저만 보이고 다음 로컬 날짜부터 전문이 열린다.
  기존 legacy 일기는 공개 상태를 유지하며, 같은 날짜에 legacy와 신규 봉인 항목이
  섞인 경우도 기존 공개 상태를 우선한다.

### 치즈냥 관계와 대사

- 첫인상의 과한 까칠함을 걷고 신입의 생명력과 책임감을 보강했다.
- 관계가 오를수록 목소리가 커지는 구조가 아니라 마음과 성장 서사가 조금씩 새어나온다.
- 관료제는 귀여운 서류 놀이의 무대이지 사용자를 심문하거나 벌주는 기관이 아니다.
- AI/강아지 등 다른 캐릭터 대사와 코드는 이 작업선에서 손대지 않는다.

### CAT HOME

- 따뜻한 원조 사무실을 기준으로 방, 고사리 화분, 집사자격증, 오늘의 원칙 게시판을
  정리했다. 방은 가로 드래그만 허용하고 세로 스와이프는 HOME 스크롤에 남긴다.
- 방 배경, 고양이, 책상 전경의 레이어를 유지한다. 고양이는 책상 뒤에 앉고 팔은 책상
  위에 놓이는 구도가 기준이다.
- 고양이 포즈는 base/blink/happy/annoyed/surprised/working/gift를 사용한다. 표정은
  잠시 나온 뒤 base로 복귀하고, idle 중에는 깜빡임과 일하는 포즈가 섞인다.
- 시간대별 방과 야간 조명 on/off가 있다. 조명이 꺼진 밤에만 고양이도 어두워진다.
- 첫 진입에서 고양이만 먼저 뜨지 않도록 방과 포즈 에셋을 미리 받는다.
- 방은 인테리어 게임이 아니라 관계 흔적을 보여주는 무대다. 선물과 관계 흔적은
  `docs/CURRENT.md`의 고정 슬롯/상한 규칙을 따른다.

### 오늘의 브리핑

- HOME 흐름은 `집사가 미리 챙길 일`과 `이미 있었던 오늘 이야기`를 분리한다. 대업은
  사용자가 고르는 입력 모드가 아니라 집사가 이야기에서 발견하는 결과다.
- 일정은 제목, 선택 시간, 완료, 사용자 선택에 의한 다음 날 넘기기만 둔다. 캘린더,
  완료율, 우선순위, 스트릭은 넣지 않는다.
- 완료 즉시 치즈냥 반응이 보이지만 완료 체크만으로 대업이나 관계 수치를 만들지 않는다.
  원하면 `오늘 이야기로 남기기`를 통해 실제 기록으로 이어지고 `sourceBriefingId`가 남는다.
- 저녁에는 평가 대신 오늘 서류를 부드럽게 덮는 짧은 정리가 나온다.
- HOME 위계는 CAT HOME과 접수 슬립, 오늘의 브리핑, 오늘 이야기 입력 순서다.

### 로고와 사운드

- 한글 로고와 작은 영문 `OVERBUTLER` 락업을 공통 헤더에 적용했다. 영문이 한글보다
  시선을 빼앗지 않는 크기가 기준이다.
- 사운드는 기본 꺼짐이며 사용자가 켠 경우에만 동작한다. 선택된 CAT-FIRST 파일은
  `design/sound-assets/final-v2/`에 있다.
- 일반 버튼과 하단 이동은 `ui-warm-move`, 완료는 `stamp-tiny-complete`, 선물은
  `gift-warm`, 관계 해금은 `relationship-unlock`을 사용한다.
- 고양이 터치는 `cat-mrrp`, `cat-nyang`, `cat-nose` 중 상황에 맞게 하나만 재생한다.
  터치 뒤 종이음이 겹쳐 날카로운 이중음으로 들리지 않게 분리했다.
- 일반 버튼음은 `click` 완료 뒤가 아니라 `pointerdown` 순간에 시작하며, MP3는 사전
  로드와 WebAudio 디코딩으로 첫 재생 지연을 줄인다.

## 4. 저장과 개인정보 방향

- 서버, 로그인, 이메일 수집 없이 `localStorage` 키 `butlermaker_v1`을 유지한다.
- 사용자가 직접 보관할 수 있는 암호화 백업/복원 흐름을 우선한다. 계정과 클라우드
  동기화는 명시적 제품 결정 전까지 추가하지 않는다.
- 새 필드는 항상 `normalizeState()`와 legacy fallback을 함께 고려한다. 기존 기록,
  선물, 관계, 일기 데이터를 초기화하거나 이름 변경으로 유실시키지 않는다.

## 6. 다음 리뷰에서 중점 확인할 것

- 신규/며칠 사용/관계 높음/일정 많음 상태에서 CAT 흐름 전체가 자연스러운지
- 360/390/430px에서 CAT HOME, 접수 슬립, 브리핑, 오늘 이야기의 위계와 겹침
- 모바일에서 일반 버튼음이 터치와 동시에 들리고 고양이 터치가 부드러운 한 소리인지
- iOS 계열 자동재생 정책 아래에서 사운드 토글 이후 첫 재생이 누락되지 않는지
- 브리핑 완료에서 오늘 이야기와 기록 상세까지 인과가 읽히는지
- legacy `butlermaker_v1` 복원 후 기록/일기/선물/관계가 유지되는지
- 집사가 사용자가 쓰지 않은 사실이나 생활 패턴을 아는 듯 말하지 않는지
- 다른 캐릭터 기능에 회귀가 없는지. 단, 평가 중 다른 캐릭터를 개선하지 않는다.

## 7. 하지 말 것

- 오너 승인 없이 merge하지 않는다.
- 다른 캐릭터 코드와 대사를 수정하지 않는다.
- CAT HOME 원조 방, 자격증/게시판, 승인된 고양이 포즈를 과거 에셋로 되돌리지 않는다.
- HOME을 일반 투두 앱이나 카드형 SaaS 화면으로 바꾸지 않는다.
- 관계 시스템, 저장 구조, CSS 전체를 정리한다는 이유로 대규모 리팩터링하지 않는다.
- 테스트 중 만든 데이터로 기존 사용자의 localStorage를 덮어쓰지 않는다.
