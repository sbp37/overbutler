# CURRENT

지금 이 저장소에서 개발을 이어갈 때 먼저 맞춰야 할 방향. `docs/PROJECT.md`(제품 개요),

## 확정/잠금 상태

아래 항목은 확정됐다. **명시적 요청 없이 다시 리팩터링하지 않는다.**

- **CAT-FIRST 유지.** 고양이 집사 하나를 완성도 있게 만드는 것이 우선이고,
  다른 캐릭터(AI/강아지/좀비/아이돌/엘프/마녀/요정/외계인/닌자)는 기존 기능이
  깨지지 않게만 유지한다. 당분간 확장 고려 대상이 아니다.
- **HOME 디자인 잠금.** `home-office.css`와 HOME 레이아웃(파일철/도장/집사방/빠른
  입력/bottom nav)은 재디자인하지 않는다.
- **HOME 단순화 잠금.** HOME 첫 화면 구조(집사방 → 오늘 이야기 → 접수서 →
  공식 인증 도장 → CTA)와, 홈에서 걷어낸 중복 요소(담당 집사 응답 카드/과몰입
  심사/선물 링크/기록 열람 섹션)는 다시 되돌리지 않는다.
- **HOME INPUT ROUTING 잠금.** 입력 분류(SHORT_ACTION/ACTION_LIST/EMOTION_ONLY/
  STORY/MIXED_STORY/FUTURE_PLAN/CASUAL_CHAT)와 FORM05 라우팅 규칙은 확정됐다.
- **미래 계획 / 완료 행동 구분 잠금.** `futurePlans`와 `activities`를 분리해서
  판정하는 방식(절 경계 기반 미래형 어미 검사)은 확정됐다. 이 로직을 추가로
  "개선"하지 않는다 — 새 회귀가 실제로 발견됐을 때만 최소 수정한다.
- **`docs/INPUT-ROUTING.md`가 입력 라우팅의 source of truth다.** 입력/응답
  로직을 고칠 일이 생기면(원칙적으로 지금은 생기지 않아야 한다) 이 문서를
  먼저 읽고, 고친 뒤에는 이 문서도 함께 갱신한다.

## 잠금과 별개인 P0 보완 (완료)

**HOME 입력 후 즉시 피드백 UX.** HOME 디자인과 INPUT ROUTING 잠금은 그대로 유지하되,
"제출 직후 집사 답이 어디에 보이는가"는 별개의 P0 보완 작업으로 처리했다.

- 집사 답변은 사용자가 [집사에게 들려주기]를 누른 자리, 즉 접수서 안 CTA 바로 아래
  카드(`#gentle-note`)에 나온다. 답을 보려고 위로 스크롤하지 않는다.
- 접수대 말풍선(cat room speech)은 첫 입장 인사·고양이 탭·방 안 짧은 반응 전용이다.
  **제출한 오늘 이야기의 PRIMARY RESPONSE 위치로 쓰지 않는다.**
- 카드 안 위계는 집사 답변이 가장 크고 먼저, 기록/도장 같은 시스템 상태는 그 아래 작게.
  "기록되었습니다" 류가 집사 답변보다 먼저·크게 나오면 안 된다.

## FORM05 고양이 보이스 (완료)

HOME의 덤덤한 츤데레와 FORM05의 고양이가 같은 캐릭터로 읽히게 맞췄다.

- 고양이 칭찬 풀 5단계를 전부 새 기준으로 교체했다. 단계가 올라가도 느낌표가 늘지
  않고, 숨기던 마음이 더 들키는 쪽으로만 자란다. **관계 상승 → 주접 볼륨 상승 구조는
  금지다.**
- 파워 주접은 고양이만 별도 풀(`CAT_POWER_PRAISE`)을 쓴다. 크게 외치는 게 아니라
  잠깐 평정심을 놓쳤다가 곧바로 수습하는 쪽 — "평소 저런 애가 왜 저래ㅋㅋ"가 목적이다.
- 파워 주접 발생률을 실측해서 낮췄다. 예전에는 `powerChanceByStage`(12~40%)에
  "처음 접수하는 분야는 무조건 폭주" 규칙이 겹쳐 **실측 48~59%** 였다. 분야가 8개뿐이라
  신규 사용자의 첫 주가 파워로 도배되는 구조였다. 보장은 생애 첫 접수 한 번만 남기고
  확률을 6~14%로 내려 **실측 10%**(20회 제출 기준 일반 18 / 파워 2)로 맞췄다.
- 고양이는 칭찬 앞에 "○○ 주인님," 호칭을 강제로 붙이지 않는다. 덤덤한 톤이 공지문처럼
  굳는다. 이름을 부를 자리는 대사 안에 `{owner}`로 직접 넣는다. 다른 캐릭터는 그대로다.
- FORM05는 재디자인하지 않고 크기/순서만 조정했다. 집사 한마디가 문서에서 가장 큰
  본문(19px)이 되고, 서식 제목은 22px로, 점수는 14px로 내렸다. 관계 블록은
  "집사가 이 기록을 챙겨뒀다" 문장이 먼저 오고 `+3`·단계·게이지가 아래로 간다.
  전부 `#id`로 걸어 FORM05에만 적용된다 (`.relationship-result`는 선물 화면과 공용).
- STORY fallback도 같이 손봤다. 분류에 안 걸리는 이야기가 전부 "응, 듣고 있다냥"
  한 줄로 떨어지던 것을, 사용자가 실제로 쓴 것(애썼다/바란다)만 가볍게 되받는
  고양이 답변으로 바꿨다. 입력 분류는 건드리지 않았고 chat-engine의 고양이 전용
  분기다. 결과를 낙관해 단정하지 않는다.

## 지금 하지 않는 것

- 화면 하나씩 완성한다. 여러 화면을 동시에 손대지 않는다.
- 생산성/투두 앱으로 만들지 않는다. 과잉집사는 사소한 일을 국가 대업으로
  접수하는 관공서 세계관이다 — 체크리스트 앱처럼 담백해지면 방향을 벗어난 것이다.
